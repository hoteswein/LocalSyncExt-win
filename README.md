# LocalSyncExt (Windows)

LocalSyncExt — фоновая синхронизация папок, отдельных файлов и файлов по маскам между двумя или несколькими местами. Приложение рассчитано на Windows; удалённые стороны можно подключать как сетевой/облачный диск или напрямую по SSH/SFTP.

Текущая версия в репозитории: **v0.7.3**. В этой версии есть консольная сборка, сборка со значком в системном трее и встроенная веб-панель. Конфигурация хранится в INI и перечитывается без перезапуска.

> **Важно о Windows-службе:** в v0.7.3 нет встроенного Service Control Manager (SCM) режима, установщика/удалителя службы или управления состоянием службы из веб-панели. Приложение нельзя устанавливать командой `sc create` как обычную службу: exe пока не реализует протокол Windows-службы. Веб-панель умеет управлять правилами синхронизации, но не запускать/останавливать ОС-службу. Это отдельная будущая функция.
>
> Также в v0.7.3 пока нет SOCKS5/HTTP-прокси для SFTP, режима резервного копирования с версиями, проверки доступности удалённых папок с запуском внешних команд и запуска пользовательских CMD/BAT/VBS/PowerShell скриптов по событиям.

## Возможности

- Двусторонняя синхронизация двух и более путей (`twoway`) и одностороннее зеркало от главного пути к остальным (`oneway`).
- Пути-папки, отдельные файлы, маски (`C:\Docs\*.pdf`), несколько локальных, сетевых, облачных и SFTP-путей в одном правиле.
- Автоматическое разрешение конфликтов либо оставление конфликтного файла без изменений для ручного решения.
- Корзина для удаляемых/заменяемых файлов, ограничение её срока хранения и выбор места для неё.
- Слежение за локальными изменениями, периодические полные проверки для удалённых путей и защита от зависших дисков.
- Интеграция с SMB/sshfs-win, rclone mount и прямыми SFTP-подключениями.
- Для прямых SFTP-путей — сохранение прав/владельца Linux-файлов при замене и обратное отображение Linux-имён, которые отличаются только регистром, на Windows через `[linux_case]`.
- Встроенная веб-панель: редактор правил, статусы, ручной запуск и пауза правил, журнал, настройки и панель SSH/SFTP-подключений.
- Автоматическое создание начального INI, если его ещё нет: без правил и пароля, веб-панель доступна только на localhost.

## Установка и первый запуск

1. Скачайте `LocalSyncExt.exe` (системный трей, без консольного окна) или `LocalSyncExt-cli.exe` (консоль) из [GitHub Releases](https://github.com/hoteswein/LocalSyncExt-win/releases).
2. Поместите exe в постоянную папку. Для первой настройки удобнее запускать `LocalSyncExt-cli.exe` из CMD/PowerShell: сообщения будут видны в консоли.
3. При отсутствии `LocalSyncExt.ini` рядом с exe программа создаст его автоматически. Начальный файл включает веб-панель на `127.0.0.1:20001`, отключает порт с авторизацией и содержит **ноль правил**.
4. Запустите приложение и откройте <http://127.0.0.1:20001/>. Через панель добавьте правило либо отредактируйте INI вручную.
5. После проверки конфигурации оставьте приложение запущенным. Для постоянной работы без трея используйте CLI-сборку; GUI-сборка автоматически запускает значок в трее.

Путь по умолчанию — `LocalSyncExt.ini` **рядом с exe**, а не в текущем каталоге CMD. Параметр `-config` позволяет выбрать другой файл. Папка для конфигурации должна существовать и быть доступна для записи; сам файл создаётся автоматически.

Установка службы Windows и автозапуск через встроенный установщик в v0.7.3 отсутствуют. Не переносите exe/INI после настройки, пока не проверили, какой именно экземпляр и какой конфиг запускаются.

## Команды командной строки

Все параметры начинаются с `-`. Указывайте их после имени exe; пути с пробелами заключайте в кавычки. В BAT/CMD предпочтительно всегда задавать полный путь к exe и `-config`.

| Команда | Назначение |
| --- | --- |
| `-config "C:\путь\LocalSyncExt.ini"` | Использовать указанный INI. Если файла нет, он создаётся автоматически в существующей родительской папке. |
| `-check` | Прочитать, проверить и вывести ошибки конфигурации, затем завершить процесс. Возвращает ненулевой код при ошибочных правилах. |
| `-once` | Выполнить один полный проход по включённым правилам и завершить процесс. |
| `-dry-run` | Не выполнять файловые изменения. Обычно применяется вместе с `-once`, чтобы посмотреть план/журнал перед реальным запуском. |
| `-version` | Напечатать версию и завершить процесс. Выполняется до загрузки INI. |
| `-tray` | Включить значок трея в консольной сборке. В GUI-сборке трей включён автоматически; для одноразовых команд он не запускается. |
| `-web-user ИМЯ -web-pass ПАРОЛЬ` | Сохранить/изменить учётные данные веб-панели и завершить процесс. Передавать оба параметра. Хранится хэш пароля, а не открытый пароль. |

Примеры:

```cmd
LocalSyncExt-cli.exe -version
LocalSyncExt-cli.exe -check -config "C:\LocalSync\LocalSyncExt.ini"
LocalSyncExt-cli.exe -dry-run -once -config "C:\LocalSync\LocalSyncExt.ini"
LocalSyncExt-cli.exe -once -config "C:\LocalSync\LocalSyncExt.ini"
```

Код возврата для автоматизации: `0` означает успешное завершение команды; `-check` и `-once` возвращают ненулевой код при обнаруженных ошибках. Сообщения и причины ошибок пишутся в консоль и журнал.

`-once` и `-check` — отдельные одноразовые режимы, они не оставляют службу/фоновый процесс. `-dry-run` не заменяет `-check`: первый моделирует проход, второй валидирует конфигурацию.

## Примеры BAT/CMD

### Проверить конфиг и выполнить один проход

```bat
@echo off
set "APP=C:\LocalSyncExt\LocalSyncExt-cli.exe"
set "CFG=C:\LocalSyncExt\LocalSyncExt.ini"

"%APP%" -check -config "%CFG%"
if errorlevel 1 (
  echo Ошибка конфигурации. См. вывод и журнал.
  exit /b 1
)

"%APP%" -once -config "%CFG%"
if errorlevel 1 (
  echo Проход завершился с ошибками.
  exit /b 1
)
echo Проход выполнен.
```

### Сначала посмотреть, что будет сделано

```bat
@echo off
set "APP=C:\LocalSyncExt\LocalSyncExt-cli.exe"
set "CFG=C:\LocalSyncExt\LocalSyncExt.ini"
"%APP%" -check -config "%CFG%" || exit /b 1
"%APP%" -dry-run -once -config "%CFG%"
```

### Запустить постоянный консольный процесс из BAT

```bat
@echo off
set "APP=C:\LocalSyncExt\LocalSyncExt-cli.exe"
set "CFG=C:\LocalSyncExt\LocalSyncExt.ini"
start "LocalSyncExt" /min "%APP%" -config "%CFG%"
```

Это запуск обычного процесса, **не установка службы**. Он продолжает работать после завершения BAT; остановить его штатно можно через `Ctrl+C` в консольном окне. Если окно было свернуто/скрыто или процесс запущен планировщиком задач, используйте штатные средства, которыми он был запущен. В текущей версии нет команды `-stop` или веб-кнопки остановки процесса. Не используйте `taskkill /F`, если важно корректно завершить текущие операции.

Для запуска с треем из CLI-сборки:

```bat
start "LocalSyncExt" "C:\LocalSync\LocalSyncExt-cli.exe" -tray -config "C:\LocalSync\LocalSyncExt.ini"
```

`LocalSyncExt.exe` (GUI-сборка) запускается сразу со значком в трее. Через меню трея можно выйти из приложения. В консольной сборке без `-tray` приложение работает без значка.

### Задать логин и пароль веб-панели из CMD

```cmd
"C:\LocalSync\LocalSyncExt-cli.exe" -config "C:\LocalSync\LocalSyncExt.ini" -web-user admin -web-pass "ЗаменитеНаСвойПароль"
```

Команда сохраняет учётные данные в каталоге состояния и завершается. Не храните настоящий пароль в общедоступном BAT-файле: аргументы могут остаться в истории команд или быть видны локальным средствам администрирования. Предпочтительнее задать пароль на странице «Настройки» веб-панели и ограничить доступ к компьютеру/порту.

## Как устроена синхронизация

### Правила и пути

Правило объединяет минимум два пути. Путь может быть папкой, отдельным файлом или маской файлов. Для масок шаблон задаётся последней частью пути, например `C:\Data\Reports\*.pdf`; остальные части пути должны быть доступны.

Внутри одного правила не смешивайте пути-файлы с путями-папками. Порядок путей важен для `oneway`: путь №1 — главный по умолчанию, если не задан `master`.

### Двусторонний режим (`mode=twoway`)

Программа сканирует участников правила и сравнивает их с сохранённой базой состояния. Новое или изменённое содержимое передаётся на остальные пути. Удаление также распространяется на другие стороны. Если путь недоступен, проверка такого правила прерывается, чтобы отсутствие файлов из-за отключённого диска не было принято за удаление.

Изменение определяется по размеру и времени изменения файла; `MtimeTol` задаёт допуск в секундах. Для облачных путей, у которых время изменения ненадёжно, программа не использует его как признак изменения и сравнивает размер. Для нескольких одновременно изменённых копий используются правила разрешения конфликтов ниже.

### Односторонний режим (`mode=oneway`)

Путь `master=N` считается источником истины. Его файлы копируются на все остальные пути; изменения только на целевых сторонах не возвращаются в источник. Файлы, появившиеся только на целевой стороне, удаляются, если `DeleteExtra=1` (значение по умолчанию). Установите `DeleteExtra=0`, если целевые файлы, отсутствующие в мастере, нужно сохранять.

### Конфликты (`conflict`)

Конфликт возникает, когда один и тот же файл изменился в нескольких местах после последнего согласованного состояния.

- `conflict=auto` (по умолчанию): обычно побеждает самая новая версия по времени изменения; при конфликте заменяемая версия сохраняется рядом под именем вида `Report.sync-conflict-20261123-124500-Disk2.xlsx`, затем выбранная версия распространяется.
- `conflict=ask`: автоматическая замена конфликтующего файла не производится; файл остаётся как есть, в журнал записывается предупреждение, а при включённых уведомлениях создаётся уведомление. Решение нужно принять вручную.

Облачное время может быть ненадёжным, поэтому в конфликте преимущество получает копия с надёжным временем. При сравнении неоднозначных вариантов могут считываться хэши файлов.

### Первичная синхронизация и защита от удаления

При первом знакомстве с путями приложение создаёт базу состояния и, если включены маркеры, служебный маркер `.lsx-…marker` в корне каждой папки. Маркер, идентификаторы папок/томов и база нужны для распознавания переименованного/подменённого диска. Для отдельного пути маркер можно отключить параметром `nomarker=N` или в редакторе правила.

При обнаружении отключённого ранее известного диска, пропавшего маркера или изменившегося серийного номера тома правило приостанавливается и ничего не удаляет. Не удаляйте файлы состояния наугад: после их удаления приложение может считать пути новыми.

Если за один проход предполагается массовое удаление (по умолчанию защита срабатывает, когда удалений не меньше пяти и доля превышает `MaxDeletePercent=50`), проход останавливается с ошибкой. Проверьте подключённость всех путей и данные, затем скорректируйте порог в правиле только если удаление ожидаемо.

### Корзина и замена файлов

Удаляемые и заменяемые файлы по умолчанию перемещаются в `.LocalSyncTrash` внутри соответствующей папки и хранятся 30 дней. Параметр `TrashDays` задаёт хранение:

- `TrashDays=30` — удалить содержимое корзины старше 30 дней;
- `TrashDays=0` — хранить бессрочно;
- пустое значение (`TrashDays=`) — удалять без корзины.

`Trash=work` выносит корзину в `WorkDir`; также можно задать отдельный абсолютный путь. Очистка корзины запускается периодически во время работы. В режиме `-dry-run` копирование и удаления не выполняются.

Большие файлы обычно записываются сначала во временный файл и переименовываются в целевое имя после завершения копирования и проверки, что источник за это время не изменился. Малые файлы по умолчанию записываются непосредственно в целевой путь (`DirectBelow=1024` КБ); `DirectBelow=0` отправляет все размеры через временный файл. `Temp=work` использует рабочую папку только когда она на том же томе, иначе временный файл создаётся рядом с целью.

Файл, который менялся совсем недавно (обычно в течение двух секунд), временно пропускается и проверяется повторно, чтобы не копировать файл в момент записи.

### Слежение и периодическое сканирование

Локальные папки Windows могут отслеживаться по файловым событиям. События объединяются с паузой `debounce`; периодический `scan` служит страховочной полной проверкой. Для сетевых/облачных путей и SFTP основной механизм — сканирование по таймеру: события с удалённой стороны могут не приходить.

Тип пути выбирается в веб-редакторе: локальный, сетевой (`remote=N`) или облачный (`cloud=N`). Номера `remote` и `cloud` начинаются с 1 и соответствуют порядку путей в правиле. Для `remote` базовое сканирование — 120 секунд, для `cloud` — 600 секунд; для локальных путей с наблюдением — страховочно 900 секунд, без наблюдения — 60 секунд. Можно задать свой `scan` в секундах; `scan=0` отключает полное сканирование, но для удалённых путей это означает, что внешние изменения могут не обнаруживаться.

Для сетевых дисков приложение ограничивает время ожидания операции. При длительном зависании правило приостанавливается; попытки восстановления повторяются с паузой, которая увеличивается до нескольких минут. До восстановления связи файлы не удаляются.

## Создание правила

Пример INI:

```ini
[Рабочие документы]
description=Документы между C и E
mode=twoway
conflict=auto
TrashDays=30
scan=60
ignore=*.bak;~$*
C:\Data\Documents
E:\Backup\Documents
```

Одностороннее зеркало, где главный путь — №1:

```ini
[Зеркало]
mode=oneway
master=1
DeleteExtra=1
TrashDays=7
C:\Data\Source
D:\Backup\Source
```

Фильтр по маске (маска включается в первый путь; остальные — папки назначения):

```ini
[PDF документы]
recursive=0
C:\Data\Reports\*.pdf
D:\PDF-backup
```

Для масок поддерживаются шаблоны `*` и `?`; обход вложенных папок задаётся `recursive=1|0`. Всегда игнорируются системные/временные файлы и внутренние временные объекты программы. Дополнительные шаблоны задаются в `ignore` через `;`, например `ignore=*.bak;*.old;~$*`.

## Параметры правил

Опции размещаются после заголовка `[Имя правила]` и до/между строками путей. Ключи не чувствительны к регистру. Для булевых параметров обычно используются `1/0`, `true/false`, `yes/no`, `on/off`.

| Параметр | Значение |
| --- | --- |
| `mode` | `twoway` или `oneway`; по умолчанию `twoway`. |
| `master` | Номер главного пути для `oneway`, начиная с 1; по умолчанию 1. |
| `conflict` | `auto` или `ask`; по умолчанию `auto`. |
| `enabled` | Включить/отключить правило; по умолчанию `1`. |
| `description` | Краткое описание, показывается в веб-панели. |
| `notify` | Уведомления Windows по конфликтам/ошибкам; по умолчанию включено, уведомления доступны в сборке с треем. |
| `ignore` | Дополнительные маски игнорируемых имён через точку с запятой. |
| `recursive` | Включить вложенные каталоги; по умолчанию `1`. |
| `watch` | Слежение за локальными изменениями; по умолчанию `1`. |
| `debounce` | Пауза объединения событий, миллисекунды; 100–60000, по умолчанию 1500. |
| `scan` | Полное сканирование, секунды; `0` выключает. Значение по умолчанию зависит от типа пути. |
| `TrashDays` | Срок хранения корзины в днях; `30` по умолчанию, `0` — бессрочно, пусто — без корзины. |
| `Trash` | `folder` (в `.LocalSyncTrash`), `work` или полный путь. Может задаваться в `[Settings]` или правиле. |
| `Temp` | `prefix` (временный файл рядом с назначением) или `work` (рабочая папка, только тот же том). |
| `DirectBelow` | Порог прямой записи в КБ; `1024` по умолчанию, `0` — всегда через временный файл. |
| `MaxDeletePercent` | Предел защиты от массового удаления, 1–100; по умолчанию 50. |
| `DeleteExtra` | В `oneway`: удалять на назначениях то, чего нет в источнике; по умолчанию `1`. |
| `NoMarker` / `nomarker` | Номера папок, где не создавать маркер, например `nomarker=2,3`. |
| `remote` | Номера сетевых путей, например `remote=2`. |
| `cloud` | Номера облачных путей, например `cloud=2`. Один путь не может быть одновременно `remote` и `cloud`. |
| `MtimeTol` | Допуск времени изменения в секундах, 0–3600; по умолчанию 2. |
| `Timeout` | Таймаут удалённого диска в секундах, 10–86400; если параметр не задан, используется значение по типу пути. |

`Trash`, `Temp` и `DirectBelow` также можно задать один раз в `[Settings]` как значения по умолчанию для всех правил. Параметр в конкретном правиле переопределяет общий.

> В INI комментарий должен занимать отдельную строку и начинаться с `;` или `#`. Не дописывайте комментарий после значения в той же строке: например, используйте `WebOpenBind=127.0.0.1`, а пояснение разместите отдельной строкой выше.

## Сетевые, облачные пути и SFTP

### SMB, sshfs-win и другие сетевые диски

Подключите диск средствами Windows и выберите его путь в правиле. Для сетевых путей задайте `remote=N`. Программа не полагается на локальные файловые события для изменений, сделанных с другого компьютера; используется периодическое сканирование и контроль зависания.

### Облака через rclone mount / bclone

Подключите облако как диск и укажите `cloud=N`. Время изменения у некоторых облаков ненадёжно, поэтому программа обнаруживает изменения по размеру. Изменение содержимого без изменения размера может быть не обнаружено. Учитывайте задержку кэша каталогов и отложенной записи самого rclone; `scan` не следует ставить чаще, чем удалённая файловая система реально обновляет список файлов.

### Прямое SSH/SFTP-подключение

В веб-панели откройте «Настройки» → «Подключения SSH/SFTP» → «Подключение». Укажите имя подключения, сервер, порт, пользователя и тип входа с паролем либо приватным ключом. Получите отпечаток сервера, сверьте его с доверенным источником и только затем подтвердите его кнопкой «Отпечаток…». Кнопкой «Проверить» убедитесь, что соединение работает.

В правиле используйте URL вида:

```ini
[Резерв на NAS]
mode=oneway
master=1
C:\Data\Documents
sftp://nas/srv/backup/documents
```

Имя `nas` должно совпадать с именем раздела `[Connection nas]`. Папки, отдельные файлы и маски поддерживаются. Пароли и парольные фразы не помещаются в INI: они хранятся зашифрованно в локальном хранилище секретов (в Windows — с помощью DPAPI). При первом соединении отпечаток хоста обязателен; при его изменении соединение блокируется до повторной проверки.

Прямой SFTP-путь считается удалённым: он проверяется по таймеру и не получает файловых событий. Через SFTP доступны права и владелец Linux; для смены владельца обычно нужен вход на сервер под `root`. Подключения через прокси в v0.7.3 не поддерживаются.

### Имена Linux, которые Windows считает одинаковыми

Linux различает `file.txt` и `File.txt`, а Windows — нет. В смешанном правиле Linux/SFTP → Windows приложение кодирует дополнительные варианты суффиксом `[linux_case]`; для нескольких совпадений используются `[linux_case2]`, `[linux_case3]` и т. д. Например `file.txt` и `File.txt` на Windows отображаются как `file.txt` и `File[linux_case].txt`. При обратной синхронизации суффиксы распознаются и убираются. Если одинаковая основа имеет расширения, различающиеся только регистром, например `report.ext` и `report.Ext`, вариант на Windows представляется как `report.Ext.ext`.

Схема нужна только для имён файлов и только когда есть Linux-сторона. Папки, различающиеся только регистром, не преобразуются; они пропускаются с предупреждением. Между двумя Linux/SFTP-путями регистр сохраняется напрямую.

## Веб-панель

Встроенная панель доступна по HTTP. Страницы и основные действия:

- **Правила** — список правил и их статусов; добавить, изменить или удалить правило; выбрать локальные папки/файлы/маски и пути SFTP; включить/отключить маркер для конкретного пути; запустить отдельное правило, поставить на паузу или продолжить; синхронизировать все правила.
- **Статус и журнал** — последнее выполнение и изменение, количества копий/удалений/конфликтов/ошибок, последняя ошибка; фильтр событий по уровню и правилу; журнал событий текущего запуска и хвост файла журнала.
- **Настройки** — сетевые параметры веб-сервера, глобальные настройки, хранение; задать логин и пароль для авторизованного порта.
- **Подключения SSH/SFTP** — добавить/изменить/удалить подключение, настроить пароль/ключ, проверить отпечаток и соединение, выбрать удалённый путь в браузере файлов.
- **Справка** — встроенные пояснения к режимам и сетевым типам путей.

Изменения конфигурации через панель проверяются перед сохранением. Предыдущая версия INI сохраняется рядом как `<config>.bak`; новая конфигурация применяется без перезапуска. При ошибочной новой конфигурации текущая рабочая конфигурация остаётся активной. Если INI параллельно изменён вручную, сохранение через браузер просит обновить страницу, а не затирает чужие изменения.

Веб-панель управляет правилами **работающего экземпляра**. Она не устанавливает программу, не запускает/останавливает Windows-процесс и в текущей версии не управляет службой SCM.

## Безопасность веб-панели

- При автосоздании конфига используется `WebOpenBind=127.0.0.1`, порт `20001`, `WebPortAuth=0`. Без пароля панель доступна только на компьютере, где работает LocalSyncExt.
- Порт без авторизации даёт полный доступ к панели и её действиям. Не меняйте bind этого порта на `0.0.0.0`, если не готовы дать доступ всей доступной сети. Особенно не публикуйте HTTP-порт в Интернет.
- Для сетевого доступа включите отдельный порт с авторизацией (`WebPortAuth`) и задайте пароль. Порт авторизации по умолчанию отключён (`0`); пользователь/пароль устанавливаются в «Настройки» либо командой `-web-user`/`-web-pass`.
- Пароль сохраняется как хэш в каталоге состояния, cookie сессии подписана, имеет флаги HttpOnly/SameSite и срок действия до 30 дней. Изменение учётных данных завершает прежние входы.
- Сервер проверяет Host/Origin и защищает изменяющие запросы от CSRF. `WebHosts` задаёт допустимые дополнительные имена узла.
- Веб-панель работает по HTTP, а не HTTPS. Для удалённого доступа используйте доверенную частную сеть/VPN и правила брандмауэра; не отправляйте пароль по недоверенной сети.

Пример безопасного локального конфига:

```ini
[Settings]
WebUI=1
WebPortOpen=20001
WebOpenBind=127.0.0.1
WebPortAuth=0
```

Если нужно открыть авторизованный endpoint в сети, добавьте, например, `WebPortAuth=20002` и `WebAuthBind=0.0.0.0`, сохраните и задайте пароль в панели. Не оставляйте доступный всем сетевым интерфейсам порт `WebPortOpen` без авторизации.

## Файлы конфигурации, состояния и журналы

- `LocalSyncExt.ini` — правила и общие настройки; по умолчанию рядом с exe.
- `LocalSyncExt.log` — текстовый журнал; по умолчанию рядом с exe. После достижения примерно 5 МБ старый файл переименовывается в `.old`.
- `state\` — база синхронизации, UI-настройки трея и web credentials; по умолчанию рядом с exe. Можно переместить через `StateDir`.
- `work\` — рабочее место для корзины и временных файлов; по умолчанию рядом с exe. Можно переместить через `WorkDir`.
- `<config>.bak` — предыдущий INI после успешного сохранения из веб-панели.

Не размещайте `WorkDir` или внешнюю корзину внутри синхронизируемой папки: иначе служебные копии могут стать входными данными для другого правила. Конфигурация перечитывается автоматически после ручного изменения; ошибочная правка записывается в журнал, а предыдущие настройки продолжают работать.

## Ограничения текущей версии

В v0.7.3 нет:

- установки, удаления, настройки или управления Windows-службой; в частности, нельзя задавать ServiceName/DisplayName/Description/ключ реестра `HKLM\SYSTEM\CurrentControlSet\Services`;
- управления ОС-службой из веб-панели;
- SOCKS5 и HTTP CONNECT proxy для прямого SFTP;
- резервного режима с сохранением версий файла по времени изменения и политиками очистки версий;
- проверки доступности удалённых папок с уведомлением и запуском внешней команды или CMD/BAT/VBS/PowerShell;
- встроенного исполнения произвольных скриптов из правил.

Эти функции требуют отдельной реализации и тестирования. Не используйте команды `sc create`, `sc start` или `sc stop` для v0.7.3: они не добавят приложению поддержки протокола Windows Service.

## Сборка из исходников и тесты

Требуется Go 1.22 или новее. Сторонние зависимости нужной версии находятся в `third_party`, поэтому проект использует локальные `replace`-директивы.

```cmd
go test ./...
go vet ./...
go build -o LocalSyncExt-cli.exe .
```

Windows GUI-сборка без консольного окна формируется CI workflow проекта с Windows-ресурсами и `guiBuild=1`; опубликованные бинарники доступны на странице [Releases](https://github.com/hoteswein/LocalSyncExt-win/releases). Изменения конфигурации сначала проверяйте командой `-check`, а при сомнениях в плане синхронизации — `-dry-run -once`.
